# FSA-Model

Repository for running an FSA model in Golang/Emergent.

The model is a modification of the CompCogNeuro `ch9/sir` PBWM simulation
(see `SIR_README.md`): instead of Store/Ignore/Recall, the network predicts the
next token of a sequence generated by a finite state automaton (FSA). The input
is the current token, the output is the prediction of the next token, and the
basal ganglia / PFC gating system has to learn to maintain the token that
disambiguates the later part of the sequence.

## The task

Tokens are `A B C D E F G H I`. `F` signals the start of a sequence. After
`F` comes either `A` or `B`, then zero or more `G`s, then one of `C`, `D` or
`E`:

```
F  A  G*  D  H      (easy)        F  A  G*  C  H      (hard)
F  B  G*  E  I                    F  B  G*  C  I
```

Each `G` repeats with probability `-prob` (default 0.5). `D` is always
followed by `H` and `E` by `I`. `C` is followed by `H` if the token before the
`G`s was `A`, and by `I` if it was `B`, so in the **hard** task the network has
to remember `A` vs `B` across the `G`s. Those `C -> H/I` transitions are the
*critical* transitions: reward (and therefore dopamine for BG learning) is
delivered only there, when the prediction is correct.

With the current settings the hard task is solved (100% correct on both
branches at every number of `G`s) in 10/10 runs, typically within 10-75 epochs.

Two measures of prediction quality are logged:

* **valid** (every trial): the prediction is one of the tokens the FSA could
  produce next from its current state (`Valid` column, `ValidPct` /
  `EpochValidPct`). Transitions such as `F -> A/B` and `G -> G/C` are random,
  so validity is the only sensible score there.
* **correct** (only after `C`, `D` or `E`): the prediction is the token that
  actually came next, `H` or `I` (`Correct` column, blank on other trials;
  `CorrectPct` / `EpochCorrectPct`). A solved model is 100% correct.

`PctErr` in the logs/plots is the fraction of invalid predictions per epoch; a
run stops early after `NZero` (default 5) consecutive epochs with no invalid
predictions.

## Building and running

The code is a self-contained Go module (`go.mod` pins the same versions of
`cogentcore`, `emergent` and `leabra` as the CompCogNeuro sims). You need Go
1.24+ and, for the GUI, the Cogent Core prerequisites (see
https://github.com/emer/leabra and https://www.cogentcore.org/core/setup/install).

```sh
git clone https://github.com/y-gokcen/FSA-Model
cd FSA-Model
go build .          # or: core build
./FSA-Model         # GUI (or: core run)
```

Headless training writes per-run CSV files into the current directory:

```sh
./FSA-Model -nogui -hard -runs 10 -epochs 1000
```

Run `N` uses random seed `N` for both the network and the token sequence, so a
rerun with the same arguments reproduces the same networks and CSV files.

Flags:

| flag | default | meaning |
|------|---------|---------|
| `-nogui` | false | run headless |
| `-hard` | false | hard FSA (both branches show `C`) |
| `-prob` | 0.5 | probability of repeating `G` |
| `-runs` | 10 | number of runs (networks) |
| `-epochs` | 1000 | max epochs per run (100 trials each); stops early on `NZero` |
| `-stripes` | 1 | number of PFC maintenance stripes (each gets a matching output stripe) |
| `-condition` | base | training environment: `base`, `noG` (no `G`s), `alwaysG` (at least one `G`) |
| `-curriculum` | false | train `noG` first, then switch to `base` at `-curriculum-switch` (default half way) |
| `-recurrent` | false | add a learnable Hidden->Hidden path and keep Hidden activity across trials |
| `-lesion-pfcoutd` | false | silence PFCoutD |
| `-test-only -weights FILE` | | skip training, test a saved weights file for `-test-trials` trials |

Output files per run (`<task>_<condition>_p<prob>_run<NN>`):

* `*.csv` – one row per training trial: FSA state, input, target, prediction,
  validity, reward, DA, RWPred, and the argmax token in each PFC stripe.
* `*_test.csv` – the same for the 10,000-trial test after training.
* `*_mtxwts.csv` – Input->MatrixGo/NoGo weights per token and stripe at the end
  of every epoch (the learned gating policy).
* `fsa_wts_*.wts.json` – the trained weights.

## Model notes

The action is in `fsa.go` and `fsa_env.go`. Relative to SIR:

* There is no control input; the Matrix layers are driven 1:1 from the Input
  layer, so the gating policy is a Go vs NoGo weight per token. The policy the
  network has to discover is: gate maintenance on `A`/`B`, do not gate on `G`
  (which would overwrite the stored token), and output-gate on `C`.
* Reward is applied only on the critical `C -> H/I` transitions, as SIR only
  rewards on Recall trials. The RW dopamine layer only produces DA when the
  reward layer is clamped, so on all other trials DA is zero and the Matrix
  synaptic traces accumulate until the outcome.
* Hidden (and Output) are cleared between trials (`Act.Init.Decay = 1`) so that
  PFC is the only cross-trial memory, except in `-recurrent` mode. The Input
  layer is also re-clamped to the new token right after it is applied: the
  standard leabra trial start hard-clamps Input *before* the new pattern is
  applied and zeroes the "already sent" activity, so without this the previous
  token was sent to Hidden in full on the first cycle of every trial. That leak
  gave the cortex a one-trial memory that, for example, solved zero-`G`
  sequences without PFC.
* After a `G` the next token is random (`G` or `C`/`D`/`E`), and the
  winner-take-all Output layer trained on random targets probability-matches
  during training and then freezes on whichever token happens to be on top.
  In the hard task both outcomes are valid. In the easy task `D`/`E` after `G`
  are branch-specific, so an easy-task run that freezes on `D` or `E` scores
  about 90% valid even though it is 100% correct after `C`/`D`/`E`.
* Hidden and Output are bidirectionally connected (the back path is what carries
  the plus-phase target into Hidden for error-driven learning). There is no
  direct Input->Output path.
* Nothing about the FSA is built into the network. The Input->Matrix weights
  that decide which tokens gate start from random values and are shaped only by
  the dopamine signal (`fsa_env.go` knows the FSA; `ConfigNet`/`ParamSets` do
  not). One consequence: the branch code a network learns is whichever
  one-bit code the random start happened to favour. Storing both `A` and `B`
  is one solution, but so is storing `F` (the start token) and letting only
  `A`, or only `B`, overwrite it, in which case PFC holds `F` on the other
  branch at the `C` trial. All of these give 100% correct predictions; the
  `*_mtxwts.csv` file shows which one a given network found.
* The number of maintenance stripes always equals the number of output stripes,
  because the fixed PFCmntD->PFCout path is a unit-level one-to-one path.

## Analyzing runs

`tools/summarize.py <dir>` reads the `*_runNN.csv` / `*_runNN_test.csv` files
in a directory and prints, per run, the number of epochs trained, the valid and
correct rates on the test trials, and the accuracy on the critical `C -> H/I`
transitions, overall, per branch, and broken down by the number of `G` tokens
that preceded the `C`.

`tools/gcount_figs.py <outdir> <test.csv> ...` (needs matplotlib) writes, per
run, three figures as a function of the number of `G` tokens in the sequence:
accuracy at the `C` trial vs overall accuracy, and the distribution of the
PFCoutD token on the `C` trial for the A branch and the B branch. Add
`--ggplot` as the first argument to reproduce the ggplot2 look (default hue
colors, no grid) of the original analysis figures.
